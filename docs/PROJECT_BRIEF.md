# Open Kiosk — Project brief

기획 기준일: 2026-11-05. 공개 자료와 팀의 검증 가설을 구분합니다.

## 1. 해결할 문제

메뉴를 이해하거나 선택을 수정하기 어려운 사용자는 주문 과정에서 원하는 선택을 끝까지 마치기 어렵습니다.
매장에서는 안내·수정 지원이 필요해지고, 이용자는 반복 입력이나 재시작에 부담을 느낄 수 있습니다.

예시 상황:
- 음성으로 담은 메뉴를 화면으로 고치려다가 진행 상황을 잃음
- 잘못 인식한 수량 하나를 바꾸기 위해 주문을 다시 시작함
- 소리가 들리지 않거나 발화가 어려울 때 다음 입력 방법을 찾지 못함

예시는 검증할 사용 상황이며, 직접 관찰한 사용자 조사 결과가 아닙니다.

## 2. 이용자와 구매 고객

- 우선 사용자: 키오스크 사용에 어려움을 느끼는 고령층·저시력 사용자
- 추가로 고려할 상황: 청각·발화·운동 기능의 차이, 소음, 복잡한 설명에 대한 부담
- 구매 고객 가설: 소규모 카페 운영자, 이후 접근성 도입을 검토하는 기관
- 최초 접점 가설: 학교 내 또는 인근 카페 한 곳
- 구매자·운영자·키오스크 이용자를 구분하고, 주문자는 가입 없이 이용하는 경험을 목표로 함

장애 유형을 묻는 가입 절차보다 필요한 기능을 선택하는 경험을 우선합니다.
당사자 검증 전에는 모든 장애인이 사용할 수 있다고 주장하지 않습니다.

## 3. 서비스 구성

### 운영자용 서비스 웹사이트
- 사회 문제·필요성·기술적 차별점 소개
- 키오스크 체험 링크와 실제 동작 시연 영상
- 요금제와 운영자 가입 데모
- 서비스 월 구독 결제 데모
- 운영 화면으로 이동하는 경험

### 고객용 키오스크
- 메뉴·옵션·수량 선택과 최종 확인
- 음성·화면·키보드 입력
- 입력 전환 시 주문 내용 유지
- 부분 수정·취소·다시 듣기·도움 요청
- 주문번호와 운영자 측 주문 확인 경험

음식값 결제는 이번 구독 결제 데모의 대상이 아닙니다.

## 4. 기술적 차별화 가설

| 가설 | 시연으로 보여줄 증거 |
| --- | --- |
| 입력 방식 전환의 연속성 | 음성으로 담은 주문을 키보드·화면으로 수정한 뒤 동일 내용 유지 |
| 맥락에 따른 부분 수정 | “두 잔 중 하나만 차갑게” 요청이 해당 옵션만 변경 |
| 메뉴에 근거한 주문 검증 | 없는 메뉴·불가능한 옵션은 확인하고 가격은 등록 정보 사용 |
| 사용자가 확정하는 주문 | 변경 내용을 확인하고 명시적 확인 후 확정 |

음성 주문과 복수 입력 방식 자체는 기존 서비스에도 있습니다.
경쟁 우위는 오류 수정·연속성·실제 사용성 검증으로 설명합니다.
공식 제품 안내만으로 경쟁사 전체의 기능 부재나 성능 차이를 단정하지 않습니다.

## 5. 사회적 영향 검증

- 독립 주문 완료: 타인의 조작 없이 의도한 품목·옵션·수량을 확인한 과제 / 시작한 과제
- 오류 수정 성공: 재시작 없이 의도대로 수정한 과제 / 오류 수정 과제
- 잘못된 최종 확정: 의도와 다른 내용으로 확정된 건수
- 도움을 선택한 상황과 이유는 별도로 기록하며 도움 요청 자체를 실패로 취급하지 않음

소규모 테스트는 참여자 수와 사용 상황을 함께 공개합니다.
장애 상황을 흉내 낸 테스트는 당사자 테스트를 대체하지 않습니다.
성능 향상·비용 절감·매출 증가의 수치 목표는 기준 측정 전 확정하지 않습니다.

## 6. 수익과 판매 가설

| 항목 | 현재 가설 | 필요한 근거 |
| --- | --- | --- |
| 지불 주체 | 매장 운영자·도입 기관 | 누가 도입과 예산을 결정하는지 인터뷰 |
| 과금 방식 | 매장 단위 월 구독 | 사용량·지원 비용·지불 의향 |
| 초기 판매 | 접근 가능한 카페에서 파일럿 제안 | 점주 인터뷰와 현장 이용 관찰 |
| 확장 판매 | 키오스크·POS 파트너와 연계 검토 | 실제 연결 가능성과 계약·지원 조건 |

고객은 무료로 주문하고, 운영자는 서비스 이용료를 내는 구조를 가정합니다.
월 요금과 판매 실적은 아직 정해지거나 검증되지 않았습니다.

경제성 검토 항목:
- 매장당 음성·AI 요청량과 실제 API 비용
- 서버·저장소·모니터링 비용
- 메뉴 등록·교육·문의 대응에 드는 시간
- 추후 결제 처리 비용과 해지·환불 운영 비용
- 실제 단말기·POS 연결이 필요할 때 발생하는 비용

매장당 기여이익은 구독 매출에서 해당 매장의 사용량 비용과 운영 지원 비용 등을 차감해 검토합니다.
지원 시간이 늘어나는 경우도 포함하며, 상용 서비스의 수익성을 보장하는 자료로 제시하지 않습니다.

## 7. 데모와 개인정보

- 실제 카드번호·결제 인증정보를 요구하지 않는 구독 데모
- 실제 이름·이메일·전화번호·비밀번호를 요구하지 않는 가상 계정 체험 목표
- 실제 주문·음성 원본·개인정보는 공개 저장소에 올리지 않음
- 데모 기능을 실제 청구·정식 회원가입·인증된 접근성 서비스로 표시하지 않음
- 실제 가입·음성 API·데이터 저장을 도입할 경우 처리 범위와 필요한 조치를 별도로 검토
