# 검증 기록

검증일: 2026-11-05. 원격 Linux 서버의 Node.js 24.13.0에서 수행했습니다.

## 자동 검사

`npm run check`의 JavaScript 문법 검사와 자격증명 패턴 검사를 통과했습니다.
`npm test`의 39개 테스트를 모두 통과했습니다. 테스트는 별도 임시 DB와 AI 비활성 설정을 사용합니다.

- 두 잔 중 하나의 온도만 변경하며 총 수량과 기존 줄 유지
- 서로 다른 입력 연산의 동일 장바구니 사용, 같은 옵션 합치기
- 알 수 없는 메뉴·품절·불가능한 온도·유효하지 않은 수량 거절
- 여러 연산 중 오류가 나면 기존 상태 보존
- 환경변수·Git·런타임 파일의 HTTP 접근 차단
- 교차 출처 변경 요청과 운영자 무인증 요청 차단
- 가상 매장 프리셋 가입과 HttpOnly 세션
- 가상 월 구독 변경과 중복 요청 처리, 실제 청구 없음
- 오래된 revision 거절, 클라이언트가 제시한 가격 무시
- 최종 금액 재검증, 중복 주문 방지, 다른 매장 주문 접근 거절
- 가격·품절 변경 후 최종 확정 시 다시 검증
- AI 연결 없음 안내와 장바구니 보존
- 해당 매장의 운영 화면으로 도움 요청 전달
- 가상 계정 삭제 시 관련 세션·키오스크 접근 제거
- 글자·이미지의 개별 확대·축소, 크기 경계와 기본값 복원
- 한국어·영어·일본어·중국어 표시 요청과 메뉴명
- 주문이 섞인 문장을 화면 전용 요청으로 잘못 소비하지 않음
- 기존 크게 보기 설정의 이전과 잘못 저장된 설정의 보정
- 배고픔·단맛에 따른 메뉴 이동과 주문·추천·확대 요청의 구분
- 음식의 온도 없음·개 단위·혼합 주문 합계와 다국어 음식명
- 실제 메뉴·품절·중복·예산에 따른 추천 검증, 모델이 제시한 가격 무시
- 추천 조합의 일괄 담기, 오류 시 일부 담기 방지와 운영 화면 전달

## 실제 OpenAI 연결

서버의 기존 키를 사용했습니다. 비밀값을 출력하거나 로컬 작업 사본으로 복사하지 않았습니다.

1. `따뜻한 아메리카노 두 잔 주세요.` → 따뜻하게 2잔, 7,000원
2. `그중 하나만 차갑게 바꿔 주세요.` → 따뜻하게 1잔 + 차갑게 1잔, 7,000원
3. OS 음성 합성으로 만든 한국어 샘플을 앱의 전사 API에 전송 → `따뜻한 아메리카노 두 잔 주세요.`로 변환 확인
4. 중국어 UI에서 `Switch to English, make the text bigger, and add one iced latte.` → 영어 전환, 글자 115%→130%, 기존 아메리카노 두 잔 유지 + 아이스 라테 한 잔 추가, 총 11,200원

실제 사람의 마이크 녹음이나 다양한 장애·발화 특성을 대상으로 한 음성 성능 평가가 아닙니다.

## Chrome 주요 흐름

- 서비스 사이트 → 가상 매장 선택 → 체험 가입
- 월 구독 결제 데모의 실제 청구 금액 0원 표시와 운영 화면 연결
- 내 매장의 전용 키오스크 연결
- 키보드 Enter로 메뉴 옵션 창 열기, 온도·수량 선택
- 화면으로 담은 두 잔을 AI 문장으로 부분 수정
- 크게 보기와 고대비 동시 적용 중 주문 수량·금액 유지
- 사용자 최종 확인 후 주문번호 발급
- 운영 화면에서 같은 매장의 접수 주문과 7,000원 체험 금액 표시
- 태블릿 테두리 안의 메뉴·주문 영역, 메뉴명과 가격 표시 확인
- 한국어·영어·일본어·중국어 전환 중 기존 주문과 금액 유지
- “글씨 크게 보여줘”는 글자만 115%, “사진 크게 보여줘”는 이미지만 115%로 변경

데스크톱 화면 배치를 시각적으로 확인했습니다. 브라우저의 390px viewport 요청이 실제로 적용되지 않아 전용 모바일 렌더링 검증은 완료하지 못했습니다. 반응형 CSS는 포함되어 있으나 모바일 검증 완료로 주장하지 않습니다.

## 현재 홈페이지 음성 시연과 자동 반영

이전 버전의 분리된 장면을 같은 화면에서 끝까지 이어지는 연속 음성 자동 반영 시연으로 교체했습니다.

- Chrome의 `/kiosk?demo=voice`에서 실제 합성 음성 MP3를 재생하고 그 파일을 전사 API로 전송했습니다. 하드코딩한 주문 결과나 인식 문장을 입력창에 주입하지 않았습니다.
- 첫 음성 “글씨가 왜 이리 작아? 글씨랑 그림을 좀 크게 키워줘!” → 글자·그림 모두 100%→140%, 큰 그림 옆에 상품명·가격을 배치
- “아이스 아메리카노 두 잔 주세요.” → 보내기 버튼 없이 차가운 두 잔, 7,000원
- “아, 그중 한 잔만 따뜻한 걸로 바꿔 주세요.” → 차가운 한 잔 + 따뜻한 한 잔, 총 두 잔·7,000원 유지
- “차가운 거에 헤이즐넛 시럽 추가해 주세요.” → 차가운 잔에만 +500원, 합계 7,500원
- 전체 과정에서 키보드 입력창은 닫혀 있고 값은 빈 문자열이었습니다. 확대된 글자와 주문 수량·온도·시럽은 유지됐습니다.
- 음성 파형, 전사 중, 요청 반영 중, 완료 상태를 연속 화면 캡처로 기록했습니다. 새 영상은 중간 장면이나 처리 대기 시간을 생략하지 않았습니다. 한 차례의 합성 음성 시연이며 일반적인 지연 시간 성능을 대표하지 않습니다.
- 최종 확인창의 시럽 표시와 7,500원 합계, 음성 동의 안내의 자동 반영 설명과 키보드 대안 열기를 확인했습니다.
- 자동 검사: 음성 요청 한 번의 자동 실행, 전사 실패·빈 결과 때 주문 미제출, 화면을 떠난 뒤 늦게 도착한 전사 결과 무시, 이미 큰 글자가 다시 작아지지 않는 가독성 요청
- 기존 추가 옵션·주문 확정·운영 화면 전달과 영상의 바이트 범위·자막·포스터 검사도 유지합니다.
- 새 31초 영상 전체를 디코딩해 오류가 없음을 확인했습니다.

연속 촬영 기록: 원본 710프레임, 화면 크기 1370×672 고정, 확대 이후 모든 프레임에서 글자·그림 140% 유지. 글자는 16→22.4px, 그림 높이는 112→156.8px로 커졌고 상품 가격이 카드 안에 표시되는지 확인했습니다. 마지막 수량 2잔·합계 7,500원입니다. 중간 영상 컷은 0개이며 숫자 기록은 `DEMO_CAPTURE.json`에 남깁니다.

모델의 주문 응답이 크기를 초기화하던 사례를 재현해, 보기 변경 의도가 없는 요청에서는 초기화·크기·언어 변경 값을 제거하는 회귀 검사를 추가했습니다.

합성 음성 시연은 실제 마이크 장치·사람의 다양한 발화 성능을 검증한 자료가 아닙니다. 녹음 원본을 서버에 보관하지 않는 정책을 유지하며 공개된 음성 샘플은 프로젝트 시연용 합성 음성입니다.

## 음식 메뉴·음성 이동·추천

Chrome의 `/kiosk?demo=menu`에서 공개 합성 음성을 재생해 실제 전사 API와 일반 음성 입력의 자동 실행 경로로 검증했습니다. 인식 문장을 입력창에 주입하지 않았습니다.

- “나 배고픈데.” → 브런치 3종 표시, 장바구니 0개·0원 유지
- “달달한 거 먹고 싶은데.” → 디저트 3종 표시, 장바구니 유지
- 두 이동 모두 글자·그림 140% 유지
- 디저트 옵션 창에 온도 선택이 없고 ‘1개 담기’와 실제 가격 표시
- “달지 않은 커피와 브런치를 만 원 안에서 추천해줘.” → 실제 GPT 추천으로 아메리카노 3,500원 + 에그 토스트 6,000원, 합계 9,500원 표시
- 추천을 보는 동안 장바구니 유지. 직접 조합 선택 → 음료 온도 선택 → 담기 후 2개·9,500원
- 영어 전환과 최종 확인창에서 음료는 `1 drink`, 음식은 `1 item`, 합계 9,500원 유지
- 메뉴 추천 버튼의 ‘만 원 안에서’ 선택도 실제 추천 API에 연결되며 이미 담긴 주문을 바꾸지 않음

추천 내용은 모델 응답에 따라 달라집니다. 위 9,500원 조합은 한 차례의 실제 결과이며 고정된 추천이나 사람 대상 성능 평가를 뜻하지 않습니다. 홈페이지의 기존 31초 영상에는 새 음식·추천 시연이 포함되지 않습니다.
