# 1차 발표와 시연

이 문서는 발표 준비용 구성안입니다. 구현 완료·사용자 테스트·출시 실적을 뜻하지 않습니다.

## 발표의 중심 문장

Open Kiosk는 사용자가 자기에게 편한 방식으로 선택하고, 실수를 고치며, 원하는 주문을 끝까지 마치도록 돕는 접근성 주문 서비스입니다.

## 1차 발표 구성

| 슬라이드 | 핵심 질문 | 준비할 자료 |
| --- | --- | --- |
| 1. 제품 소개 | 어떤 문제를 해결하는가? | 가칭·태그라인·서비스 한 문장 |
| 2. 사회 문제 | 누가 어느 단계에서 어려움을 겪는가? | 출처 있는 조사와 실제 인터뷰 구분 |
| 3. 필요성과 기존 대안 | 기존 서비스로 충분하지 않은 지점은? | 모델·지역을 구분한 경쟁 사례 |
| 4. 기술적 차별점 | 무엇을 실제 동작으로 입증하는가? | 입력 전환·부분 수정·메뉴 검증 |
| 5. 접근성·UI | 필요한 기능을 쉽게 선택할 수 있는가? | 화면·키보드·읽어주기 경험 |
| 6. 브랜드와 서비스 사이트 | 누가 구독하고 왜 구매하는가? | 운영자 사이트·요금제·가입 데모 |
| 7. 개발과 통합 | 구성 요소가 어떻게 함께 동작하는가? | 구현한 구조만 표시하고 예정 기능 구분 |
| 8. 실제 시연 | 가입부터 매장 이용까지 연결되는가? | 구독 데모·키오스크·운영 화면 |
| 9. 검증과 다음 단계 | 확인된 점과 남은 가설은? | 테스트 범위·한계·사업 검증 계획 |

수업 1주차 항목과의 연결:
- 문제 정의와 사회적 영향력 분석: 2·3·9
- AI 디자인 브랜딩 & UI: 1·5·6
- AI 코딩 개발 환경과 백엔드: 7
- AI 코딩 서비스 통합 개발: 7·8

## 시연 이야기

1. 점주가 서비스 사이트에서 문제와 제품 설명을 본다.
2. 키오스크 데모를 확인하고 가상 운영자 가입을 체험한다.
3. 월 구독 상품의 결제 데모를 완료한다. 실제 청구가 없음을 표시한다.
4. 고객용 키오스크에서 “글씨가 왜 이리 작아? 글씨랑 그림을 좀 크게 키워줘!”로 글자와 그림을 140%로 키운다.
5. “아이스 아메리카노 두 잔 주세요”를 말하고 자동으로 담긴 두 잔을 확인한다.
6. “그중 한 잔만 따뜻한 걸로”로 온도를 나누고, “차가운 거에 헤이즐넛 시럽 추가”로 해당 잔만 바꾼다.
7. 두 잔·7,500원과 확대 유지, 필요할 때 키보드 대안을 열 수 있음을 보여준다.
8. 최종 확인 버튼으로 확정한 뒤 운영 화면에서 같은 매장의 주문을 확인한다.

홈페이지 영상은 합성 음성 파일을 실제 전사·주문 API에 넣어 자동 반영하는 화면입니다. 실제 사람의 마이크 녹화와 구분합니다. 새 영상은 중간 장면·대기 시간 생략 없이 같은 화면에서 확대 상태를 유지합니다.

서비스 구독과 음식값 결제를 혼동하지 않도록 설명한다.
실제 동작 영상과 화면 목업을 구분하고, API가 연결되지 않은 기능도 정확히 표시한다.

추가 메뉴 시연은 `/kiosk?demo=menu`에서 진행할 수 있습니다. “나 배고픈데” → 브런치, “달달한 거 먹고 싶은데” → 디저트로 이동하며 주문과 확대 상태가 유지되는지 보여줍니다. 이어 “달지 않은 커피와 브런치를 만 원 안에서 추천해줘”로 실제 메뉴·가격을 사용하는 추천을 열고, 직접 조합과 음료 온도를 선택해 담습니다. 실제 검증에서는 아메리카노와 에그 토스트 9,500원이 추천됐으며 결과는 모델 응답에 따라 달라집니다. 추천과 주문 확정을 분리하고 서버가 가격·판매 상태·예산을 검증하는 점을 설명합니다.

## 검증 기록

일반 `/kiosk`의 새 진입 흐름은 언어·읽어주기·마이크 동의를 준비한 뒤 ‘음성·화면 함께 시작’으로 들어갑니다. 버튼 없이 말소리 후보를 감지하고 안내가 끝나면 다시 대기하며 화면 선택도 함께 사용할 수 있습니다. 영어 주문에는 메뉴와 음성 안내도 영어로 맞춥니다. 온도 확인 후 짧은 답변, 메뉴·주문 읽기, 추천 순번 응답과 최종 확인을 시연할 수 있습니다. 홈페이지의 기존 영상에는 새 자동 감지·다국어 대화 흐름이 포함되지 않습니다. 실제 소음·장애 당사자 평가는 후속 과제로 구분합니다.

- 테스트한 버전과 환경
- 참여자 수·사용 상황·과제
- 원하는 주문을 완료했는지
- 수정·입력 전환에서 발생한 오류
- 도움 요청과 그 이유
- 개선 전후 차이와 아직 확인하지 못한 부분

## 2차 발표로 이어질 내용

- 사용자 피드백을 반영한 개선
- 매장 운영자의 도입 의향과 지불 의향
- 실제 사용량을 바탕으로 한 비용·요금 가설
- 판매 경로와 파일럿 운영 계획
- 검증된 사실을 중심으로 한 IR 피치
- 체험 URL 또는 시연 영상 등 실제 제공한 런치 결과
